# План развития Deep.js

## Требования к ✅ завершению пункта:
- Полное покрытие тестами
- Бенчмарки сравнивающие с как минимум 1 альтернативным решением
- Документация
- Автоматическое применение в gh-actions и иных облачных решениях если это возможно

## Основные компоненты

### События (Events) ✅
Реализация системы событий, без проблем с лимитом на количество листнеров как у EventEmitter
Методы доступны из любой ассоциации on once off emit.
Экземпляр эмиттера создается когда появляется первая подписка, и забывается когда последняя подписка умерла.

### Память (Memory) ✅
Эффективное управление отдельным вектором памяти для релейшенов.
Отвечает за создание одного вектора одиночные-множественные отношения.

### Ассоциации (Association) ✅
Базовый функционал класса обертки ассоциации и проксирования методов.
Позволяет обернуть что угодно в deep(?). Создает аморфную проксируемую сущность - ассоциация.
Дает доступ ко всему добавленному к прокси объекту.
Не является самим предметом данных, но слоем доступа к чему угодно, универсальной единицей восприятия.
Все ассоциации вызываемые. Если в ней функция - она будет вызвана, если нет то то что в ассоцации будет возвращено.
Любые данные соприкасаясь с любым методом ассоциативным или попадая в deep(?) становятся ассоциациями.

### Жизненный цикл (Lifecycle) ✅
Рождение и смерть ассоциаций с событиями и глобальной коллекцией живых ассоциаций.
Методы доступны из любой ассоциации: kill. Выбрасывает событие kill.
С момента создания и до смерти теперь любая ассоцация есть в ассоциативном множестве all.

### Проверка типов (Is) ✅
Проверка на соответствия единообразно доступные из любой ассоциации.
Предоставляет филды доступные из любой ассоиации которые не требуют вызова: isString isNumber isBoolean isArray isObject isFunction isNull isUndefined isSymbol isBigInt isDate isRegExp isSet isMap isPromise isError isJSON isEmpty isMany isPlainObject
Так-же предоставляет способ сравнения ассоциаций ass1.is(ass2)

### Методы доступа (Gets) ✅
Доступ к ассоциациям и их свойствам.
Предоставляет классические методы работы с множествами: has get keys values entries forEach map filter find reduce.
Все методы работают из любой ассоциации поверх любого типа данных единообразно.
Все входящие аргументы могут быть любым типом данных, и становятся ассоциациями если ими не являются.
Все каллбеки и результаты возвращаюта ассоциативные данные.

### Методы изменений (Sets) ✅
Изменение ассоциаций и их свойств.
Предоставляет методы доступные из всех ассоциаций: set add delete remove push pop shift unshift.
Методы пораждают события как имени собственного так и несколько стандартных как add/remove для отслеживания колебаний множеств единообразно если включен трекинг.

### Работа с множествами (Many) ✅
Предоставляет difference intersection symmetricDifference union для универсальной работы с множествами.
Оперирует sets операциями чем пораждает события add/remove если включен трекинг.

### Отношения (Relations) ✅
Реализации Memory для релейшенов
Предоставляет из любой ассоциации пары одиночных и множественных переходов по векторам:
Типизация к родителю .type и к наследникам .typed.
Графовый вектор влево .from и на исходящие .out и вправо .to и на входящие .in.
Ссылка на значение ассоциации (не путать с .this содержанием) .value указывает на другую ассоциацию и на тех кто считает ее своим значением .valued.
Все методы возвращают ассоциативные множества поддерживающие трекинг и события, всегда актуальные после получения.

### Отслеживание (Track) ✅
Способность любых методов трансформации данных (sets gets many) вызывать созависимости событий, что бы интерактивно точечно перевычислять только часть результата.
Предоставляет .track поле возвращающее активный трекер, после чего исходные .origins этого трекера (по умолчанию то множество откуда вызвано, но в случае например в ass.union(ass2, ass3) там все три ассоциативных множества) становятся интерактивно обновляемыми и всегда актуальными без полного перевычисления.


### Коллекция трекера 🛠️
Позволяет после получения трекера подключать коллектор который следит за событиями с определенной частотой вызывая или вообще не вызывая события. Собирает список изменений в свое содержание. Возвращает и опусташает список если вызвать коллектор. Позволяет при создании указать delay time что бы уменьшить частоту срабатывания.

### Поиск (Select) 🛠️
Поддержка выражений для поиска поассоциативным данным с поддержкой подписок на результаты.
Предоставляет универсальный диалект deep.select({ type typed from out to in value valued this }) где значения в ключах могут быть как конкретной ассоциацией так и вложенным {} выражением.
🛠️ Поддерживает .track полученного результ сета что делает результат всегда актуальным без полного перевычисления результата.
✅ Если .select() вызывается из deep ассоциации, или ассоциации содержащей не множество, то поиск будет по всей ассоциативной памяти.
🛠️ Если .select() вызывается из ассоциативного множества, то поиск будет фильтровать содержание не выходя за его пределы.

```javascript
const selection = deep.select({ type: A, to: { type: B } });
const collector = selection.track.collect(1000); // 1000ms delay каталогизация событий трекера selection
```

### Отложенность или планнер 🧪
Поддержка отложенного выполнения для всех (sets gets many select) сущностей.
Позволяет создать план запроса, где в качестве разрашения определенного вычисления есть не только нативный поиск по ассоциациям но структура адаптеров асинхронного вычисления из внешних баз данных.
Формально это механизм активации и смены состояний.
Предоставляет .plan .start .stop.
То есть result = ass.plan.map(f).filter(f) сработает не сразу, а только когда будет выполнен result.start. Это верно и для result = ass.plan.select(exp). Формально result получает .type = plan, что меняет поведение всех методов.
После вызова start result начинает выполняться.
Если до этого сделать await result() то промайс не будет выполнен пока не будет вызван start и не получится результат.
Учитывая что все операции происходят используя sets gets many и прочие операции - на каждом шагу будут создаваться ассоциативные события.
Все события пробрасываются на уровень result плана что позволяет отслеживать отдельные колебания по пути вычислений.

### Базы данных 🧪
Адаптеры асинхронности для PostgreSQL MongoDB SQLite Файловая система
Здесь есть ряд любопытных подходов и способов:
При работе с файловой системой мы имеем структуру похожую на Contain связь от родительской условно директории (некоторая ассоциация) к дочерним (ассоциациям) файлам и папкам. Что позволяет искать по ним как по реальным ассоциациям, просто результат асинхронен, однако получив его раз - он подвержен трекингу и все последующие обращения к результатам будут давать актуальные результаты.
При работе с PostgreSQL важно что каждая таблица, колонка, строка, поле, значение - это ассоциация, просто не обязательно выгружаемая сразу. Агрегационные данные о количестве или структуре данных позволяет создать множество типов представленных ассоциациями, доступными для использования в .select() что значит что на этапе написания запросов мы можем не знать что за данные будут в таблице и результатах.
Это применимо к любым источникам данных делая их единообразно представимыми как ассоциативное множество. И нам не нужно хранить их в своей памяти что бы использовать в .select() и воспринимать как единообразно воспринимаемые данные.

### ass.id() 🧪
Вычисляемый только при необходимости идентификатор uuid. Устанавливается если при извлечении известно что у сущности есть id.
Поддерживает множественность идентификаторов если сущность представлена в нескольких источниках.
ass.id.sourceName() позволяет получить id с точки зрения конкретного источника но не присваивает его без нужды.
Механика источников будет реализовываться на уровне задачи Базы данных и подключения к внешним источникам.

### AI и MCP

#### .ai(?) запрос
Базовый доступ к общению с ии по умолчанию, так-же доступному как терминальная утилита deep7 ai.
Может принимать множество аргументов как контекст. В том числе может принимать результат select запроса. Примечательно что если у него будет включен трекинг то данные будут всегда актуальны в контексте.
```js
const result = await deep.ai('Какой сегодня день?');
```

#### .ai проекси слои
```javascript
// Заранее инициализируются ассоциации нейронок, провайдеров и стандартов
deep.ai.standarts.OpenAI = new deep.ai.Standart({ /* описание стандарта */ });
deep.ai.providers.OpenRouter = new deep.ai.Provider({ /* описание провайдера с указанием стандарта */ });
deep.ai.models['Claude-3.7-Sonnet'] = new deep.ai.Model({ /* описание модели с указанием провайдера */ });
// Установка по умолчанию
deep.ai.standarts.default = deep.ai.standarts.OpenAI;
deep.ai.providers.default = deep.ai.providers.OpenRouter;
deep.ai.models.default = deep.ai.models['Claude-3.7-Sonnet'];
```

#### Поддержка автоформирования контекста

Если в запрос передать любую ассоциацию она станет контекстом. Если это результат запроса - это так-же сработает и он вычислится даже если требует асинхронных вызовов к внешним источникам.

```javascript
// Получение данных для обработки AI
const userData = deep.select({ /* ... */ });

// Использование данных для AI-обработки
const summary = await deep.ai(userData, 'Суммаризируй профиль пользователя');
```

#### Цепочки вызовов

```javascript
const decomposition = deep(plan => plan
  .ai('Проанализируй можно ли разбить задачу на подзадачи, и если возможно сгенерируй план действий как json массив из строк или объектов')
  .map(decomposition));
const execute = deep(plan => plan
  .ai('Исполни этот шаг плана')
const pipeline = deep((message) => deep.plan
  .ai(message)
  .ai(deep.ai.models.chatgpt, 'Суммируй и сгенерируй отчет')
  .ai(deep.ai.models.deepseek, 'Сгенерируй план действий как json массив из строк или объектов')
  .map(decomposition)
  .map(execute)

const work = pipeline('Захвати мир');
work.start;
await work();
```

#### Операции
Позволяет регистрировать операции которые будут выполняться по инициативе ai.
В глобальном deep.ai.operations можно добавлять операции deep.ai.operation.name = new deep.ai.Operation(f) которые становятся доступны для всех моделей.
При выполнении deep.ai можно передать операции в качестве входящих аргументов и они будут доступны в контексте.

#### Агентная система

Агенты в Deep.ai представляют собой автономные модули с различными возможностями:

```javascript
const agent = deep.ai.agent({
  capabilities: ['search', 'calculate', 'write'],
  memory: 'long-term',
  tools: ['web-search', 'calculator']
});
```

**Capabilities (Возможности)**
- **Определение**: Предопределенные наборы функций, регистрируемые как ассоциации
  ```javascript
  deep.capability('search', {
    description: 'Поиск информации в интернете',
    parameters: {...},
    execute: async (params) => {...},
    examples: [{...}]
  });
  ```
- **Типы**: Базовые (`search`, `calculate`, `write`), Расширенные (`analyze`, `summarize`, `translate`), Кастомные (пользовательские)

#### Системы памяти

Механизмы сохранения и восстановления контекста:

**Типы памяти**:
- **short-term**: Контекст текущей сессии
- **long-term**: Персистентное хранилище с векторной БД
- **conversational**: Оптимизирована для диалогов
- **episodic**: "Эпизоды" взаимодействия
- **semantic**: Смысловые связи и контекст

```javascript
const memory = deep.ai.memory('conversational', {
  summarization: true,
  maxTokens: 4000,
  windowSize: 20
});
```

### Комплексные AI-решения

#### Ассистенты

Комбинированные системы, использующие различные компоненты AI:

```javascript
const smartAssistant = deep.ai.assistant({
  name: 'ShopAssistant',
  // Статические данные (единоразовый запрос)
  staticData: {
    catalog: deep.select({ type: productCatalog }),
    company: deep.select({ type: companyInfo })
  },
  // Реактивные обновления
  reactiveChains: [
    {
      watch: deep.select({ type: userBehavior }).track,
      pipeline: 'behaviorAnalysis'
    }
  ],
  // Кешированные состояния
  states: [
    userRecommendationsState,
    currentPromotionsState
  ],
  // Интеграция с другими системами
  connectors: {
    paymentSystem: paymentAPI,
    deliveryTracker: deliveryAPI
  }
});
```

#### Мульти-модальные цепочки

Обработка различных типов данных в единой цепочке:

```javascript
const multimodalChain = deep.ai.chain([

  {

  {
    type: 'tts',
    model: 'elevenlabs',
    input: 'imageDescription',
    output: 'audio'

// Запуск цепочки
const result = await multimodalChain.run({
  imagePrompt: 'Футуристический город с летающими машинами'

```
