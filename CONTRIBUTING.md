# Руководство по участию в разработке deep7

## Общие принципы

1. Каждый функционал должен быть полностью протестирован
2. Все изменения должны быть задокументированы
3. Производительность критична - все изменения должны быть протестированы на производительность

## Структура проекта

- `*.js` - исходные файлы с реализацией функционала
- `*.test.js` - тесты для проверки функционала
- `*.benchmark.js` - бенчмарки для измерения производительности
- `*.md` - документация (название без расширения заглавные буквы)
- `*.note.md` - заметки и черновики документации (не попадают в git)
- `*.experiment.js` - файлы для экспериментов (не попадают в git)

## Процесс разработки

### 1. Тестирование

Запуск всех тестов:
```bash
npm test
```

Запуск всех тестов (без отладки):
```bash
NODE_OPTIONS='--no-inspect' npm test
```

Запуск конкретного теста:
```bash
npm test [name].test.js
```

### 2. Бенчмарки

#### Запуск всех бенчмарков и обновление документации:
```bash
npm run benchmarkify
```

#### Запуск конкретного бенчмарка и обновление его документации:
```bash
BENCHMARK="track.benchmark.js" npm run benchmarkify
```

Доступные опции:
- `DEBUG=true` - включает режим отладки
- `QUICK=true` - запускает минимальное количество тестов
- `TIMEOUT=60` - устанавливает таймаут в секундах (по умолчанию 120)
- `MAX_DURATION=30` - максимальное время выполнения бенчмарка в секундах

### 3. Документация

- Каждый файл функционала `[name].js` должен иметь соответствующие файлы:
  - документации `[NAME].md`
  - тестов `[name].test.js`
  - бенчмарков `[name].benchmark.js`
- В документации обязательно должен быть раздел "## Производительность" после первого заголовка
- Результаты бенчмарков автоматически обновляются в соответствующих md-файлах

### 4. Процесс внесения изменений

1. Создать ветку для новой функциональности
2. Написать тесты
3. Реализовать функционал
4. Написать бенчмарки
5. Обновить документацию
6. Создать PR

## Правила оформления кода

1. Используйте встроенные пакеты Node.js где возможно
2. Все публичные методы должны быть документированы
3. Все сложные алгоритмы должны иметь комментарии
4. Следуйте принятому стилю кода

## Работа с производительностью

1. Каждое изменение должно иметь бенчмарк
2. Результаты бенчмарков должны быть в документации
3. При оптимизации:
   - Сначала измерьте
   - Затем оптимизируйте
   - Снова измерьте
   - Документируйте результаты
